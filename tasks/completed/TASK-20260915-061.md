## Result

Completed as a read-only reconciliation. The configured production identity is provable as
the local Docker PostgreSQL database `football` on `localhost:5432`, backed by the named
volume `football-agent_pgdata`. It is not a canonical 0021 database: it contains only the
`alembic_version` table with value `0021`; 17 canonical business tables and their data are
absent.

The latest preserved complete 0021 candidate is
`football_reconcile_current_preflight_20260830` with 18 tables, 7,624 fixtures, 569
predictions, 6,469 teams, 465 competitions, zero bookmakers and zero odds snapshots. This
is a preserved clone, not current production, and was not promoted or modified.

Production was last evidenced with 7,719 fixtures, 576 predictions, one canonical Bet365
row and zero odds snapshots on 2026-08-31. No preserved source containing that complete
state was found, so recovery requires an explicit rehearsal and an accepted delta recovery
plan.

Static audit found three integration modules that fall back to the production settings DSN
when `TEST_DATABASE_URL` is absent and execute `Base.metadata.drop_all()` during teardown.
Their execution timing is tightly correlated with the schema-loss window and explains why
`alembic_version` alone survived. PostgreSQL statement logging was disabled, so this is a
high-confidence root-cause conclusion rather than definitive statement-level attribution.
