## Ordered writer re-enable plan

1. Runtime foundation: deploy a persistent API from the clean release, without the dirty bind
   mount, and rebuild a fresh declared-dependency Windows virtual environment. Require persistent
   API health/ready, pip check, scheduler imports, DB 0021 and Redis health.
2. Controlled DailyProductionRun: with separate approval, run exactly one controlled invocation
   while the recurring task remains Disabled. Audit every row delta, API request, bookmaker
   creation, duplicate key, heartbeat, timeline and log.
3. Daily recurring task: only after the controlled run passes, enable DailyProductionRun alone and
   observe one scheduled cycle.
4. Pre-kickoff: perform a separately approved natural T-90/T-60/T-30 canary. Enable
   PreKickoffValidation only after provider provenance, bookmaker identity, rate limits and
   duplicate snapshot checks pass.
5. Settlement: enable SettlementFallback after the upstream fixture/value-bet lifecycle is healthy
   and settlement/bankroll idempotency has been demonstrated.
6. Recovery last: enable ProductionRecoveryCheck only after DailyProductionRun has a healthy
   heartbeat. Recovery can invoke DailyProductionRun inline and therefore must be last.

At every stage, preserve a single enabled writer, verify one full cycle, and disable it again if any
acceptance check fails.
