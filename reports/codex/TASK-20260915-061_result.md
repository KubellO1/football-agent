## 5. 高可信根因

静态审计发现以下 integration test modules：

- `tests/integration/test_backfill.py`
- `tests/integration/test_backtest.py`
- `tests/integration/test_daily_job.py`

它们都采用 `TEST_DATABASE_URL` 存在时使用 test DSN，否则回退到 `get_settings().sqlalchemy_dsn`，并在 fixture teardown 执行 `Base.metadata.drop_all()`。

这绕过了 `tests/integration/conftest.py` 已有的 `require_test_database_url()` 保护；公共保护明确要求 `TEST_DATABASE_URL` 存在且数据库名以 `_test` 结尾。

当环境未显式提供 `TEST_DATABASE_URL` 时，这三个 fixture 会连接 production `football`。`Base.metadata.drop_all()` 删除映射业务表，但 `alembic_version` 不属于 `Base.metadata`，正好解释为什么最终只剩 revision marker。

时间证据也吻合：

- TASK-20260903-048 的 `.pytest_cache` 创建于 2026-09-03 08:55:02 Europe/Paris。
- 该任务报告 `103 passed` integration，并于约 09:22 完成报告。
- PostgreSQL 大规模 checkpoint activity 发生于 09:03–09:05 Europe/Paris。

根因分类：`HIGH_CONFIDENCE_TEST_DATABASE_SAFETY_DEFECT_NOT_FORENSICALLY_PROVEN`。

由于 exact test command/environment 和 DROP statements 未被持久记录，不能做司法级唯一归因；但代码行为、遗留 schema 形态和时间线三者一致。

另一个放大因素：application role `football` 当前是 PostgreSQL superuser 且拥有 CREATEDB，因此错误 DSN 具备删除 production schema 的权限。
