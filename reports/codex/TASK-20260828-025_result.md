## 已确认的代码断点

```text
Odds-API.io response market "ML"
  → OddsApiIoProvider: BookmakerMarket.market = "1x2"
  → OddsIngestionService: if market.market != "h2h": continue
  → no bookmaker creation
  → no OddsSnapshot
  → no DB persistence
  → verify() returns no_snapshots
  → NO_ODDS_TRUE
```

当前 skip 分支也没有增加 `outcomes_skipped`，所以运行摘要无法直接暴露 market-key mismatch。现有 provider 单测明确断言 `market == "1x2"`，而 ingestion 测试使用的是 `market="h2h"`；缺少真实 provider-output → ingestion 的组合契约测试。

## Fixture / event matching

- Provider 内先用球队名 + kickoff ±180 分钟做一次匹配，然后 `/odds/multi`。
- Ingestion 再用同一候选做第二次保守匹配。
- 第二次匹配启用人工别名；第一轮 provider-side mapping **未传入别名解析器**，可能在调用 multi 之前漏掉本可识别的 event。
- `ProviderFixtureMapping` 只有领域实体，没有 ORM、repository 或 migration；生产没有持久 provider event ID mapping。
- `normalize_team_name` 实际会剥离 `FC/AFC/SC/City/Town/Wanderers/and Hove Albion`，但模块顶部注释声称不会剥离，文档与执行行为不一致。

这些是 mapping 风险，但 9 个已经成功到达 ingestion 的 event 仍全部因 market-key mismatch 丢失，因此后者是当前 snapshot=0 的确定性直接根因。

## Timestamp / freshness

适配器只读取 `market.updatedAt`；若缺失则 `last_update=None`，ingestion 会拒绝整个 market。现有 Redis 中仅剩 rate-limit keys，没有未过期原始 event payload；根据“不调用外部 API”的限制，本任务不能验证付费接口当前真实 timestamp 字段位置。

该项属于**待验证 latent freshness/normalization 风险**，不是当前第一断点。需要单独批准一次最小、脱敏、受控 API probe。

## Persistence 与 retrieval

- Snapshot repository 使用 `uq_odds_snapshots_natural` 的 `ON CONFLICT DO NOTHING`，天然幂等。
- DB session 在正常退出时 commit，异常时 rollback。
- Retrieval 按 `fixture_id` 且 `captured_at <= as_of` 查询。
- Quote verifier 再按 30 分钟 freshness、1X2 selection、outlier 和 bookmaker 数量验证。

因为 production 从未创建 bookmaker/snapshot row，目前没有证据支持 persistence bug、retrieval bug、覆盖 bug 或 timezone freshness bug。它们不应被当作已证实根因。

## Bet365-only 与 minimum_bookmakers=2

执行链：

```text
.env ODDS_API_IO_BOOKMAKERS=["Bet365"]
  → Settings.odds_api_io_bookmakers
  → build_odds_provider(... bookmakers=...)
  → /odds/multi bookmakers=Bet365

Settings.analysis_odds_min_bookmakers default=2
  → build_market_quote_policy()
  → VerifiedMarketQuotePolicy(minimum_bookmakers=2)
  → each home/draw/away selection requires len(kept) >= 2
```

因此单一 Bet365 即使每场成功写入 3 条 1X2 snapshot，也会分别得到 `insufficient_bookmakers:home/draw/away`，无法进入 RecommendationGate。建议在 paid 权限下通过独立配置审批启用并验证至少第二家 bookmaker；**不建议降低 minimum_bookmakers 来制造推荐**。
